# CI Reliability Analytics

## Repository conventions

- Use English for all repository content, including documentation, code comments, report text, commit messages, issues, milestones, and pull requests.
- Keep the GitHub repository public from creation. Review every staged change before publishing. Keep credentials, personal data, employer data, and local tool settings outside the repository. Publish only samples and examples suitable for public distribution.
- Use descriptive commits and link pull requests to issues. Document the purpose of each change, the evidence supporting material decisions, and how the change was verified.
- Document reproducible setup in the README and run the same local verification path in CI.

## Power BI

- Use the local Microsoft Power BI Authoring MCP to work with measures, relationships, and semantic models. Use a test model with a publishable sample and compare selected DAX results with SQL.
- Version reports as PBIP projects with PBIR report definitions and TMDL semantic models. Verify visual rendering and interactions in Power BI Desktop. Keep local Power BI settings, caches, and report exports out of Git.
